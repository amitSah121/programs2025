    1. Unsafe/Reserved Characters (Should be Avoided) 
    
					
    These characters have special meanings in URLs and should not be used in API paths: 
    

					
    
						
    
							Character
							Reason	
						
    
						
    
							?
							query parameters (e.g., /api/data?id=123)
						
    
						
    
							&
							Separates query parameters (e.g., /api/data?x=1&y=2)
						
    
						
    
							=
							Used for key-value assignment in query strings
						
    
						
    
							#
							Used for URL fragments (ignored in requests)
						
    
						
    
							%
							Used for URL encoding (e.g., %20 for space)
						
    
						
    
							+
							Sometimes treated as space in URLs
						
    
						
    
							\
							Backslashes can cause parsing issues
						
    
						
    
							"
							Double quotes are not URL-safe
						
    
						
    
							'
							Single quotes can interfere with parsing
						
    
						
    
							<, >
							Angle brackets can be interpreted as HTML
						
    
						
    
							`	`
						
    
					
    

					
    2. Special Symbols (Can Be Used with Encoding)
    
					
    These symbols are technically allowed but require proper encoding:
    

					
    
						
    
							Character	
							URL Encoding
						
    
						
    
							/	
							Encoded as %2F (Avoid using inside dynamic parameters)
						
    
						
    
							:	
							Encoded as %3A (Used for parameters in REST APIs)
						
    
						
    
							@	
							Encoded as %40
						
    
						
    
							[ ]
							Encoded as %5B and %5D (Used in IPv6 addresses)
						
    
						
    
							{ }
							Encoded as %7B and %7D (Used in API documentation)
